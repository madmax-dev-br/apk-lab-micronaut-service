Segurança e limites

O runner executa código de APKs (o bytecode do app, interpretado pela VM do lab) e, se você permitir, JavaScript de plugins. Trate o acesso à API como acesso de execução nesta máquina.

Modelo de segurança

  • Quem pode chamar: o runner aceita só o portador de RUNNER_TOKEN; a fila aceita os clientes de QUEUE_CLIENTS e isola os jobs e leases de cada um. Exponha a fila, não o runner; ponha HTTPS na frente.
  • O que o APK alcança: o app roda dentro da VM (Dalvik interpretado em JavaScript). Ele não executa código nativo da máquina: bibliotecas .so do APK só funcionam onde o lab tem uma implementação em JavaScript/WebAssembly do mesmo comportamento; o resto falha com erro explícito. Arquivos do app ficam no sistema de arquivos virtual da VM (e, com RUNNER_APP_DATA_DIR, num diretório por cliente).
  • Processo por sessão: cada sessão é um processo Node com ambiente mínimo (sem os segredos do runner), heap limitado e timeouts; o APK chega como arquivo do diretório daquela sessão, que é apagado ao fechar.
  • Leitura de arquivos pelo Worker: o shim do Worker só serve arquivos de dentro do diretório do runtime; qualquer outro file: é recusado.
  • Entrada validada duas vezes: records Java com Bean Validation (chaves desconhecidas são erro) e depois os sanitizadores do próprio bundle do lab (presets do aparelho, regras de host, mocks, assinaturas de método, permissões). Limites de tamanho: APK (RUNNER_MAX_APK_MB), corpo, config (8 MiB), mocks (50, 4 MiB cada), linhas do protocolo.
  • O runtime baixado é conferido arquivo por arquivo (tamanho e SHA-256) contra sidecar/runtime.lock.json, fixado num commit do repositório público do site.

Rede

  • Como no site, uma sessão alcança todo host público por padrão (allowedHosts ["*"], teto RUNNER_ALLOWED_HOSTS="*"). O operador pode restringir os hosts que as sessões liberam, redirecionam ou usam como proxy (none = só mocks).
  • Rede interna recusada. O servidor não é o navegador de um visitante: "qualquer host" incluiria os serviços da própria máquina, a rede privada e o endpoint de metadados da nuvem. Toda troca HTTP da VM resolve o nome antes (dns.lookup, todos os endereços, no shim do Worker e no worker de rede do bundle) e é recusada quando algum endereço é loopback (127.0.0.0/8, ::1), privado (10/8, 172.16/12, 192.168/16, fc00::/7), link-local (169.254.0.0/16 — inclusive 169.254.169.254 —, fe80::/10) ou não especificado (0.0.0.0/8, ::). Vale para a requisição direta, para cada salto de redirecionamento e para hostMap. O app recebe uma java.io.IOException que nomeia a política (NetworkPolicyError: RUNNER_ALLOW_PRIVATE_NETWORK: ...) e o log de rede mostra a falha. Mocks respondem antes de qualquer rede.
  • RUNNER_ALLOW_PRIVATE_NETWORK=true libera esses alvos (homologação local, por exemplo): ligue só para usuários confiáveis, num runner isolado. Limite conhecido: um nome cuja resposta DNS muda entre a verificação e a conexão (DNS rebinding) não é pego; isole o runner na rede também.
  • apkUrl da fila só baixa de hosts em QUEUE_APK_URL_HOSTS, sem seguir redirecionamentos, com limite de tamanho.

Plugins

Desligados por padrão. RUNNER_ALLOW_PLUGINS=true permite que quem tem o token rode JavaScript no servidor. Ligue só para usuários confiáveis.
  • Cada plugin roda no sidecar da sessão, num worker_threads Worker próprio com resourceLimits (RUNNER_PLUGIN_HEAP_MB), num contexto node:vm que só tem timers, console (descartado) e a ponte de mensagens: sem process, require, import(), fetch nem o ambiente.
  • Um watchdog mede a utilização da thread do plugin de fora: ocupado acima de 90% por RUNNER_PLUGIN_BUSY_S segundos seguidos, o plugin é encerrado e relatado; RUNNER_PLUGIN_MAX_RUN_S limita a duração total.
  • A API lab é somente leitura (tela, layout bounds, ViewModels, campos, Logcat, rede, imagens): o plugin não toca, não digita e não muda a config.
  • worker_threads e node:vm não são uma fronteira de segurança. Eles removem as capacidades óbvias e limitam memória e CPU, mas código malicioso determinado pode escapar de um contexto vm. Para usuários não confiáveis, mantenha os plugins desligados ou rode cada runner num contêiner/VM descartável sem segredos e sem rede interna.

Limitações

  • APIs não implementadas falham explicitamente. Quando o app chama uma API Android/JDK que a VM ainda não tem, a operação falha com um erro que nomeia a API (422 vm-error, detalhes no /diagnostic). O modo tolerante (missingApis: void, primitives, all) troca a falha por stubs, sempre relatados no diagnóstico e no snapshot; nunca há sucesso fingido em silêncio.
  • Código nativo protegido não é simulado. Bibliotecas nativas que protegem ou decodificam os dados do próprio app (verificação de integridade, detecção de root/emulador, criptografia, anti-fraude, pagamento, atestação) não são reimplementadas, substituídas nem contornadas, e a identidade do aparelho não é alterada para passar nessas verificações. Um app que depende delas para funcionar para nesse ponto, com o erro.
  • WebView: no servidor não há navegador para desenhar páginas de WebView; a área aparece como um retângulo vazio no screenshot (X-Screenshot-Notes: webviews), e o conteúdo web não é executado.
  • Screenshots: o que a VM desenha (Compose, Canvas, fundos, parágrafos Skia) é exato; texto simples de widgets XML que o site desenha com o DOM é aproximado com a Roboto do bundle e contado em approximatedText.
  • Áudio, câmera, sensores reais, Bluetooth não existem no servidor; o que o lab simula (localização, bateria, conectividade) é configurável pela API.
  • Desempenho: a VM interpreta bytecode em JavaScript. Nos testes deste repositório, numa máquina de desenvolvimento: carregar um APK Compose pequeno leva ~0,45 s, iniciar ~1,2 s, um toque por semântica 30–40 ms, digitação ~0,1–0,2 s, layout bounds ~30 ms, um screenshot 40–50 ms; um job de 10 passos terminou em ~2,8 s. Apps grandes levam bem mais, e cada sessão usa centenas de MiB.
  • Fidelidade: o comportamento do framework vem dos originais do AOSP (Android 13) que o lab usa, e a VM declara SDK_INT 33; apps que dependem de serviços do Google Play podem não rodar.
