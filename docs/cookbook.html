Cada receita tem a versão em curl e a versão em Java com o HttpClient do Micronaut. Os nomes de pacote e de host (com.exemplo.app, api.exemplo.com) são ilustrativos: troque pelos do seu app.

Preparo

export R=http://127.0.0.1:8081 T=$RUNNER_TOKEN      # runner
export Q=http://127.0.0.1:8080 C=token-do-cliente   # fila
Java (Gradle: implementation("io.micronaut:micronaut-http-client")) 
import com.fasterxml.jackson.databind.JsonNode;
import io.micronaut.http.HttpRequest;
import io.micronaut.http.MediaType;
import io.micronaut.http.client.BlockingHttpClient;
import io.micronaut.http.client.HttpClient;
import io.micronaut.http.client.multipart.MultipartBody;
import java.net.URL;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;
import java.util.Map;

HttpClient client = HttpClient.create(new URL("http://127.0.0.1:8081"));
BlockingHttpClient http = client.toBlocking();
String token = System.getenv("RUNNER_TOKEN");
byte[] apk = Files.readAllBytes(Path.of("app.apk"));

// cria uma sessão com uma config (JSON) e devolve o id
String criar(String config) {
    MultipartBody body = MultipartBody.builder()
            .addPart("apk", "app.apk", MediaType.of("application/vnd.android.package-archive"), apk)
            .addPart("config", config)
            .build();
    JsonNode created = http.retrieve(HttpRequest.POST("/sessions", body).contentType(MediaType.MULTIPART_FORM_DATA_TYPE).bearerAuth(token), JsonNode.class);
    return created.path("session").path("id").asText();
}

1. Sessão criada já com um mock de endpoint

O app pede GET https://api.exemplo.com/v1/perfil; o lab responde 200 com JSON sem a requisição sair da VM. Nenhum host precisa estar liberado. A linha da requisição no log de rede vem marcada com mockId e mockLabel, e o Logcat registra um aviso APKWebLab: endpoint mockado no primeiro uso.

curl -s -H "Authorization: Bearer $T" -F apk=@app.apk -F 'config={
  "endpointMocks": [{
    "name": "perfil", "method": "GET", "url": "https://api.exemplo.com/v1/perfil", "status": 200,
    "headers": [{"name": "Content-Type", "value": "application/json"}],
    "body": "{\"nome\": \"Ana\", \"plano\": \"premium\"}"
  }],
  "launch": true
}' $R/sessions | tee sessao.json
S=$(jq -r .session.id sessao.json)

# use o app até ele pedir o perfil (aqui: tocar no botão que carrega)
curl -s -H "Authorization: Bearer $T" -H 'Content-Type: application/json' -d '{"selector": {"text": "Perfil"}}' $R/sessions/$S/tap > /dev/null
curl -s -H "Authorization: Bearer $T" "$R/sessions/$S/network" | jq '.requests[] | {method, url, status, mockId, mockLabel}'
# {"method": "GET", "url": "https://api.exemplo.com/v1/perfil", "status": 200, "mockId": "m-…", "mockLabel": "perfil"}
Java 
String id = criar("""
    {"endpointMocks": [{"name": "perfil", "method": "GET", "url": "https://api.exemplo.com/v1/perfil", "status": 200,
                        "headers": [{"name": "Content-Type", "value": "application/json"}],
                        "body": "{\\"nome\\": \\"Ana\\", \\"plano\\": \\"premium\\"}"}],
     "launch": true}""");
http.retrieve(HttpRequest.POST("/sessions/" + id + "/tap", Map.of("selector", Map.of("text", "Perfil"))).bearerAuth(token), JsonNode.class);
JsonNode network = http.retrieve(HttpRequest.GET("/sessions/" + id + "/network").bearerAuth(token), JsonNode.class);
for (JsonNode row : network.path("requests")) {
    System.out.printf("%s %s -> %d (mock: %s)%n", row.path("method").asText(), row.path("url").asText(), row.path("status").asInt(), row.path("mockLabel").asText());
}

Este fluxo (criar com mock, iniciar, tocar, ler o log de rede) é o teste CookbookClientTest do repositório, rodado com um APK de sonda sintético.

2. Mock por padrão de caminho, query, corpo, status e atraso

Um 500 depois de 2 s para qualquer POST de pedidos cujo corpo contenha "urgente": true, em qualquer host; aplicado ao vivo numa sessão aberta. O primeiro mock habilitado que casa (na ordem da lista) responde.

curl -s -X PATCH -H "Authorization: Bearer $T" -H 'Content-Type: application/json' -d '{
  "endpointMocks": [
    {"name": "pedido urgente falha", "method": "POST", "url": "/v2/pedidos*", "query": "ignore",
     "bodyContains": "\"urgente\": true", "status": 500, "reason": "Internal Server Error",
     "headers": [{"name": "Content-Type", "value": "application/json"}],
     "body": "{\"erro\": \"indisponível\"}", "delayMs": 2000},
    {"name": "busca exata", "method": "GET", "url": "https://api.exemplo.com/v1/busca?q=monitor&pagina=1", "query": "exact",
     "status": 200, "body": "[]"}
  ]}' $R/sessions/$S/config | jq '.applied'
Java 
var falha = Map.of("name", "pedido urgente falha", "method", "POST", "url", "/v2/pedidos*", "bodyContains", "\"urgente\": true",
        "status", 500, "headers", List.of(Map.of("name", "Content-Type", "value", "application/json")),
        "body", "{\"erro\": \"indisponível\"}", "delayMs", 2000);
JsonNode applied = http.retrieve(HttpRequest.PATCH("/sessions/" + id + "/config", Map.of("endpointMocks", List.of(falha))).bearerAuth(token), JsonNode.class);

No log de rede a requisição aparece com status 500, durationMs por volta de 2000 e o mockLabel.

3. Redirecionar um host

As requisições do app para https://api.exemplo.com vão para um servidor seu em 127.0.0.1:9000 (HTTP comum; o app continua achando que falou com o host original). O destino precisa caber em RUNNER_ALLOWED_HOSTS do runner (padrão *), e um destino em loopback ou na rede privada, como 127.0.0.1, só é alcançado com RUNNER_ALLOW_PRIVATE_NETWORK=true no runner (sem ele, o app recebe uma IOException que nomeia a política).

curl -s -H "Authorization: Bearer $T" -F apk=@app.apk -F 'config={
  "network": {"hostMap": [{"from": "https://api.exemplo.com", "to": "127.0.0.1:9000"}]},
  "launch": true}' $R/sessions | jq -r .session.id
# no log de rede: "url": "https://api.exemplo.com/...", "mappedUrl": "http://127.0.0.1:9000/...", "mappedRule": "https://api.exemplo.com → 127.0.0.1:9000"
Java 
String id = criar("""
    {"network": {"hostMap": [{"from": "https://api.exemplo.com", "to": "127.0.0.1:9000"}]}, "launch": true}""");

from aceita esquema, porta e curinga (*.exemplo.com); to aceita host:porta ou uma URL. Um destino fora da política do runner é recusado com 403 network-policy.

4. Lista de hosts permitidos e modo offline

# só estes hosts (cada um dentro de RUNNER_ALLOWED_HOSTS); o resto falha como sem DNS e aparece com "refusedHost" no log de rede

# aparelho sem rede (o ConnectivityManager também diz offline); mocks continuam respondendo

6. Override do retorno de um método

Força o retorno de um método do app (por exemplo, uma flag de funcionalidade) sem recompilar. Use GET /sessions/{id}/methods?query=checkout para achar a assinatura.

curl -s -X PATCH -H "Authorization: Bearer $T" -H 'Content-Type: application/json' -d '{
  "methodOverrides": [{"method": "Lcom/exemplo/app/Flags;->novoCheckout()Z", "value": "true"}]}' $R/sessions/$S/config | jq '.applied[0].statuses'
Java 
http.retrieve(HttpRequest.PATCH("/sessions/" + id + "/config",
        Map.of("methodOverrides", List.of(Map.of("method", "Lcom/exemplo/app/Flags;->novoCheckout()Z", "value", "true")))).bearerAuth(token), JsonNode.class);

Overrides são uma ferramenta de depuração do comportamento do seu próprio app. Eles não servem para contornar proteções (verificação de integridade, detecção de root, anti-fraude): veja Segurança e limites.

10. Job na fila com passos e seus resultados

curl -s -H "Authorization: Bearer $C" -F apk=@app.apk -F 'job={
  "label": "fluxo de pedido", "priority": 7, "collect": {"network": true},
  "config": {"endpointMocks": [{"url": "https://api.exemplo.com/v1/perfil", "body": "{\"nome\": \"Ana\"}"}]},
  "steps": [
    {"type": "launch"},
    {"type": "wait", "selector": {"text": "Pedidos"}, "timeoutMs": 20000},
    {"type": "type", "selector": {"testTag": "busca"}, "text": "Monitor"},
    {"type": "tap", "selector": {"testTag": "pedido-2"}},
    {"type": "layoutBounds", "name": "caixas"},
    {"type": "screenshot", "name": "detalhe"},
    {"type": "viewModelField", "viewModel": "PedidosViewModel", "path": "estado.value"}
  ]}' $Q/jobs | tee job.json
J=$(jq -r .id job.json)
curl -N -H "Authorization: Bearer $C" $Q/jobs/$J/events        # progresso; termina no estado final
curl -s -H "Authorization: Bearer $C" $Q/jobs/$J | jq '{state, steps: [.result.steps[] | {type, ok, ms}], artifacts: [.result.artifacts[].name]}'
curl -s -H "Authorization: Bearer $C" -o detalhe.png $Q/jobs/$J/artifacts/detalhe.png
Java 
HttpClient fila = HttpClient.create(new URL("http://127.0.0.1:8080"));
String clientToken = System.getenv("QUEUE_CLIENT_TOKEN");
String job = """
    {"label": "fluxo de pedido", "steps": [{"type": "launch"}, {"type": "wait", "selector": {"text": "Pedidos"}},
     {"type": "tap", "selector": {"testTag": "pedido-2"}}, {"type": "screenshot", "name": "detalhe"}]}""";
MultipartBody body = MultipartBody.builder()
        .addPart("apk", "app.apk", MediaType.of("application/vnd.android.package-archive"), apk)
        .addPart("job", job).build();
JsonNode submitted = fila.toBlocking().retrieve(HttpRequest.POST("/jobs", body).contentType(MediaType.MULTIPART_FORM_DATA_TYPE).bearerAuth(clientToken), JsonNode.class);
String jobId = submitted.path("id").asText();
JsonNode state;
do {
    Thread.sleep(500);
    state = fila.toBlocking().retrieve(HttpRequest.GET("/jobs/" + jobId).bearerAuth(clientToken), JsonNode.class);
} while (List.of("queued", "assigned", "running").contains(state.path("state").asText()));
byte[] png = fila.toBlocking().retrieve(HttpRequest.GET("/jobs/" + jobId + "/artifacts/detalhe.png").bearerAuth(clientToken), byte[].class);

Cada passo fica em result.steps com ok, ms e output (ou error com o código do runner, por exemplo element-not-found); com continueOnError um passo pode falhar sem encerrar o job. Falhas de infraestrutura (runner fora, sidecar caído) repetem o job em outro runner.

Java (Gradle: io.micronaut.reactor:micronaut-reactor) 
import io.micronaut.http.client.sse.SseClient;
import io.micronaut.http.sse.Event;
import reactor.core.publisher.Flux;

SseClient sse = SseClient.create(new URL("http://127.0.0.1:8081"));
Flux.from(sse.eventStream(HttpRequest.GET("/sessions/" + id + "/logcat/stream").bearerAuth(token), JsonNode.class))
    .filter(event -> "log".equals(event.getName()))
    .map(Event::getData)
    .subscribe(line -> System.out.println(line.path("level").asText() + " " + line.path("tag").asText() + ": " + line.path("message").asText()));

Enquanto nenhum stream está aberto, a VM não manda linhas de Logcat ao servidor (custo zero); abrir o primeiro stream liga o envio e manda as linhas recentes.

13. Plugin no servidor observando um campo de ViewModel

Exige RUNNER_ALLOW_PLUGINS=true (só para usuários confiáveis: veja Segurança). O código é o de um plugin do site: a API lab somente leitura.

    const lista = await lab.viewModels();
    const vm = lista.find(v => v.className.endsWith('PedidosViewModel')) ?? lista.find(v => !v.library);
    if (!vm) { lab.ui.text('Nenhum ViewModel na tela'); return; }
    lab.ui.badge(vm.className.split('.').pop());

Num job, o passo {"type": "plugins", "plugins": [...], "seconds": 10} roda os plugins por 10 s e guarda a saída (imagens viram artefatos); exige QUEUE_ALLOW_PLUGINS=true e um runner com plugins.

15. CORS

A VM no servidor não precisa de CORS. As requisições HTTP do app saem do processo sidecar (Node), não de um navegador: não existe origem nem preflight para elas. No site, o app roda dentro do navegador e por isso o servidor da API do app precisa liberar a origem do site; aqui, não.

CORS só importa para a API do runner ou da fila quando um front end no navegador a chama de outra origem. Desligado por padrão; ligue com a lista exata de origens:

RUNNER_CORS_ORIGINS=https://painel.exemplo.com,http://localhost:5173 ./gradlew :runner:run
QUEUE_CORS_ORIGINS=https://painel.exemplo.com ./gradlew :queue:run
JavaScript no navegador 
const R = 'https://runner.exemplo.com';
const res = await fetch(`${R}/sessions/${id}/tap`, {
  method: 'POST',
  headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({ selector: { testTag: 'salvar' } }),
});
// EventSource não envia cabeçalhos: o token vai como access_token (só em GET)
const logs = new EventSource(`${R}/sessions/${id}/logcat/stream?access_token=${encodeURIComponent(token)}`);
logs.addEventListener('log', event => console.log(JSON.parse(event.data).message));
const png = URL.createObjectURL(await (await fetch(`${R}/sessions/${id}/screenshot.png`, { headers: { Authorization: `Bearer ${token}` } })).blob());
  • O preflight (OPTIONS) é respondido antes da autenticação; uma origem fora da lista recebe 403 cors-origin-not-allowed.
  • Não há cookies: a autenticação é por token, então Access-Control-Allow-Credentials não é enviado nem necessário.
  • Os cabeçalhos expostos ao navegador: X-Image-Size, X-Screenshot-Notes, X-Screen-Ready, Retry-After, Content-Disposition.
  • Um token no navegador é visível para quem usa a página: dê ao front end um token de cliente da fila (com limite próprio) em vez do token do runner sempre que possível.

16. Recarregar a tela

Dois jeitos de recarregar a Activity atual, como os botões "Recriar" e "Reabrir" do site:

  • recreate (padrão): Activity.recreate(), o que o Android faz numa rotação ou troca de tema. Estado salvo e ViewModels retidos ficam. Use para testar se a tela sobrevive a uma mudança de configuração (o texto digitado volta? a lista não é buscada de novo?).
  • reopen: uma instância nova com o mesmo Intent no lugar da atual, sem estado salvo e com o ViewModelStore limpo; o conteúdo carrega de novo. Use para buscar os dados outra vez depois de trocar um mock (PATCH /config) ou para voltar a tela ao estado inicial sem reiniciar o app (/restart recarrega o APK inteiro).
curl -s -H "Authorization: Bearer $T" $R/sessions/$S/view-models | jq '.[] | select(.library | not) | .handle'      # "h6755.…"
curl -s -H "Authorization: Bearer $T" -H 'Content-Type: application/json' -d '{"mode": "recreate"}' $R/sessions/$S/reload | jq '{mode, activity: .snapshot.activity}'
curl -s -H "Authorization: Bearer $T" $R/sessions/$S/view-models | jq '.[] | select(.library | not) | .handle'      # o mesmo handle: ViewModel mantido
# troca o mock e carrega de novo numa instância nova
