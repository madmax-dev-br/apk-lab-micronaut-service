Referência da API

Runner em http://127.0.0.1:8081, fila em http://127.0.0.1:8080 por padrão. Os exemplos usam $R (URL do runner), $T (token do runner), $Q (URL da fila) e $C (token de um cliente da fila).

Convenções e erros

  • JSON em UTF-8. Chaves desconhecidas em qualquer corpo são erro 400 (um erro de digitação nunca é ignorado em silêncio).
  • Coordenadas e limites em dp da tela; bounds são relativos à janela de conteúdo e screenBounds somam a barra de status.
  • Erros: {"error": {"code": "...", "message": "...", "details": {...}}}. O message e os details da VM são os do lab (por exemplo, a API Android que faltou).

Criar sessão

POST /sessions

Três formatos, todos com resposta 201:

# multipart: parte "apk" (arquivo) e parte opcional "config" (JSON)
curl -H "Authorization: Bearer $T" -F apk=@app.apk -F 'config={"launch": true}' $R/sessions

# APK cru; config no cabeçalho X-APK-Config (JSON ASCII ou base64url do JSON)
curl -H "Authorization: Bearer $T" -H 'Content-Type: application/vnd.android.package-archive' \
     -H 'X-APK-Config: {"launch":true}' --data-binary @app.apk $R/sessions

# JSON com o APK em base64
curl -H "Authorization: Bearer $T" -H 'Content-Type: application/json' \
     -d "{\"apkBase64\": \"$(base64 < app.apk | tr -d '\n')\", \"config\": {\"launch\": true}}" $R/sessions
{"session": {"id": "5efd76bf-...", "state": "running", "packageName": "com.exemplo.app", "launcherActivity": "com.exemplo.app.MainActivity",
             "activity": "com.exemplo.app.MainActivity", "metrics": {"loadMs": 440, "launchMs": 1150, "operations": 2}, "runtimeRevision": "93d82df0437e", ...},
 "inventory": {"packageName": "...", "usesSdk": {"minSdkVersion": 24, "targetSdkVersion": 34}, "activities": [...], "usesPermissions": [...], ...},
 "config": { ...a config normalizada... },
 "snapshot": { ...resumo da tela, se já houver uma... }}

A sessão é criada em um processo sidecar novo; se a carga falhar (APK inválido, config recusada pelos sanitizadores, exceção do app), a sessão é fechada e o erro volta com o status certo.

ChaveRegras
devicePresets e valores do painel do lab: screen phone|compact|large|small|tablet, orientation portrait|landscape, connectivity online|offline|metered, navigation gesture|buttons, fontScale 0.85–2, locale xx-YY, timeZone IANA.
network.allowedHostshost, *.sufixo, host:porta, IP ou *; cada entrada precisa caber em RUNNER_ALLOWED_HOSTS (403 network-policy).
network.hostMapRedireciona from (esquema, host, porta, curingas) para to; o destino também passa por RUNNER_ALLOWED_HOSTS. Até 50 regras.
network.offlineA VM fica sem rede (ConnectivityManager incluso); mocks continuam respondendo.
network.proxyUrlRelay HTTPS (ou HTTP em loopback); {url} marca onde vai o destino codificado.
permissionsstates: allow|deny|ask por permissão; dialogs: dismiss (padrão) | manual | allow | once | deny.
methodOverridesAté 100; método em descritor Dalvik ou pacote.Classe.metodo(...); valor literal (true, 42, "texto", null).
ignoredActivitiesAté 100; string ou {"name", "enabled"}.
endpointMocksAté 50; method ANY|GET|POST|PUT|PATCH|DELETE|HEAD|OPTIONS; url com http(s):// ou começando com / (qualquer host), * como curinga; query ignore|exact; status 200–599; corpo até 4 MiB (body ou bodyBase64); delayMs até 600000.
eventSeconds0 ou 60 | 120 | 300: quanto um evento de entrada pode rodar na VM.

Logcat, rede e eventos

GET /sessions/{id}/logcat?since=&limit=500&level=W&tag=&contains= → {"lines": [{"seq", "level", "tag", "message", "thread", ...}], "next", "more", "total", "dropped", "streaming"}
GET /sessions/{id}/logcat/streamSSE: um evento log por linha, id = seq; ?since= ou Last-Event-ID retoma.
GET /sessions/{id}/network?since=&limit=200 → {"requests": [{"seq", "method", "url", "status", "outcome", "mockId", "mockLabel", "mappedUrl", "refusedHost", "durationMs", ...}], ...}
GET /sessions/{id}/network/streamSSE: evento request por linha (de novo quando completa).
GET /sessions/{id}/eventsSSE: session (descrição inicial), snapshot, loaded, runtime-error, permission-request, permission-config, app-data, plugin, crashed, closed.

As linhas do Logcat só saem da VM enquanto alguém escuta (um stream aberto, um plugin que pediu logs, uma leitura paginada em andamento ou "logcat": "always"). Todo stream manda ping a cada 15 s e termina quando a sessão fecha.

Jobs

POST /jobs → 202

# multipart: "apk" + "job" (JSON)
curl -H "Authorization: Bearer $C" -F apk=@app.apk -F 'job={"priority": 7, "steps": [{"type": "launch"}, {"type": "screenshot", "name": "inicio"}]}' $Q/jobs
# APK cru + X-Job (JSON ASCII ou base64url) · JSON com apkBase64 · JSON com apkUrl (host em QUEUE_APK_URL_HOSTS)
{"config": {...config da sessão...}, "steps": [...], "priority": 5, "timeoutMs": 300000,
 "collect": {"logcat": true, "network": true}, "label": "smoke", "maxAttempts": 3}

Sem steps, o job só inicia o app. Resposta: o job com id, state (queued → assigned → running → succeeded | failed | cancelled), position na fila, attempts.

GET /jobs?state=Os jobs do cliente (mais novos primeiro, até 500).
GET /jobs/{id}O job com result: steps (index, type, ok, ms, output ou error), artifacts (name, type, bytes, url), session (pacote, runner, tempos).
GET /jobs/{id}/eventsSSE: queued, assigned, running, step-started, step-finished, retry, e o estado final (o stream termina nele).
GET /jobs/{id}/artifacts/{name}Screenshots PNG e dumps JSON.
POST /jobs/{id}/cancel · DELETE /jobs/{id}Cancela (na fila ou rodando: o passo atual é interrompido e a sessão fechada).

Agendamento: maior prioridade (0–9, padrão 5) primeiro; na mesma prioridade, o cliente com menos itens rodando; depois o mais antigo. Cada cliente tem até QUEUE_MAX_PER_CLIENT (ou o próprio limite) itens com sessão. O job vai para o runner saudável com mais vagas (health menos o que a fila já atribuiu desde então). Retentativas: runner inacessível, 5xx, sidecar caído ou VM parada repetem o job em outro runner até maxAttempts com espera crescente; runner cheio repete sem contar tentativa; falha de um passo do app não repete.

Leases interativos

POST /leases → 202

{"config": {...}, "priority": 5, "durationSeconds": 900, "waitSeconds": 60, "label": "depuração"}

Mesmos formatos de envio do APK que /jobs (parte multipart lease). O lease entra na fila; quando um runner tem vaga, vira active com expiresAt e a sessão criada. A partir daí, toda a API de sessão do runner fica em /leases/{id}/session/...:

curl -H "Authorization: Bearer $C" -H 'Content-Type: application/json' -d '{"selector": {"testTag": "salvar"}}' $Q/leases/$L/session/tap
curl -H "Authorization: Bearer $C" -o tela.png $Q/leases/$L/session/screenshot.png
curl -N "$Q/leases/$L/session/logcat/stream?access_token=$C"
GET /leases · /leases/{id} · /leases/{id}/eventsEstado (queued, active, expired, cancelled, failed), posição, expiração.
POST /leases/{id}/extend{"seconds": 300} (até QUEUE_LEASE_MAX_S desde o início).
DELETE /leases/{id}Encerra e fecha a sessão no runner.

O lease expira por duração (lease-max-duration), por inatividade sem chamadas pelo proxy (lease-idle; streams abertos contam como uso) ou por esperar na fila mais que waitSeconds (lease-wait-timeout).
